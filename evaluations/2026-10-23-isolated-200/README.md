## 실제 확인 범위

- 체크포인트 요청 200건의 종료를 확인했고, LLM2 입력 경계 176개에서 HISTORY 기록·B02 호출은 0건입니다.
- 입력 경계는 부모 상태를 `InvestigatorState` 필드로 투영한 검사입니다. 별도 네트워크 프롬프트 캡처는 아니며, 그래프 격리 회귀 테스트와 함께 해석합니다.
- 노드별 도구 수는 체크포인트의 trace 증가분입니다. HTTP 요청 수나 재시도 수, 검색 정확도가 아닙니다. `DUPLICATE_CALL` 1건은 내부 중복 차단 기록입니다.
- LLM2는 R01 77회·R02 84회, 최종 실행기는 R05 97회·SDR→AMM 조회 29회를 기록했습니다. R03·R04 호출은 관찰되지 않았습니다. 미사용이 미구현을 뜻하지 않습니다.
- 실행 당시 단위·회귀 테스트 173건 통과가 기록돼 있습니다. 해당 로그 전체를 이 번들에 포함한 것은 아닙니다. 이번 게시용 도구 검증 및 현재 CI 결과와 구분합니다.
- 라벨 검토 상태는 미검토 161건, 최종 검토 필요 24건, 결정 완료 15건입니다. 실제 항공 정비의 안전성·진단 정확도를 입증한 평가가 아닙니다.
- 42건의 보류가 모두 타당하거나 모두 불필요했다고 판단하지 않았습니다. 예측 일치와 보류 사유의 적절성은 별도 검토가 필요합니다.
- 동일 조건의 개선 전후 비교가 아닌 1회 실행입니다. 실행 중 프롬프트·검색 순위를 튜닝하지 않았습니다.
- Backend 온라인 의존성 다운로드 실패로 로컬 Gradle 캐시에서 빌드한 최신 소스 JAR을 런타임 이미지에 사용했습니다. 깨끗한 환경의 온라인 Docker 빌드 성공을 증명하지 않습니다.
- 프런트엔드 health 확인은 포함하지만 화면 조작·브라우저 종단간 테스트 결과는 아닙니다. AWS 배포 검증도 아닙니다.

## 버전과 재현

`full-eval-results.json`의 `freeze.repositories.ai`는 격리 수정 전 **기준 커밋**입니다.
그 커밋만 checkout하면 평가 당시 실행 코드를 재현하지 못합니다.
실제 실행한 AI 파일은 `freeze.ai_source_sha256`의 34개 해시로 식별하며,
수정 후 커밋 [b3dc87e](https://github.com/mro-agent-proj/LLM/commit/b3dc87ee4e069367c1478518cccf32bf49f7314d) 및
게시 준비 시 LLM main의 같은 34개 파일과 모두 일치하는 것을 확인했습니다.
나머지 서비스 기준 커밋과 데이터셋·시드 SHA256도 `freeze`에 보존했습니다.
당시 컨테이너·큐·DB 전체의 재현 이미지를 제공하는 번들은 아닙니다.

이 폴더에서 파일 무결성을 확인합니다 (Linux는 `sha256sum -c SHA256SUMS`):

```bash
shasum -a 256 -c SHA256SUMS
```

LLM·backend·deliverables를 같은 상위 폴더에 받은 후 LLM 루트에서:

```bash
python3 scripts/evaluation/summarize_full_eval.py \
  --bundle ../deliverables/evaluations/2026-10-23-isolated-200 \
  --dataset ../backend/data/eval/service/scenarios.jsonl --check
```

실행 DB나 API 키 없이 결과를 재집계하고 데이터셋 해시·채점·감사를 대조합니다.
새 실구동 테스트가 아닙니다. 도구 설명은
[LLM 평가 도구](https://github.com/mro-agent-proj/LLM/tree/main/scripts/evaluation)를 참고합니다.
새 평가 데이터로 바뀌면 새 폴더를 만들고 이 실행 자료는 덮어쓰지 않습니다.
